# @lumen/tokens

Design tokens generated from the Lumen-AI-Design-System Figma file — the
single source of truth for color, typography, spacing, radius, motion, and a
growing set of other categories (see below). Every other Lumen package
(`@lumen/ui`, `@lumen/patterns`, `@lumen/web-components`, `@lumen/angular`)
consumes these tokens rather than hardcoding any value.

## Consuming this package

```ts
// CSS custom properties (:root for light, [data-theme="dark"] for dark)
import "@lumen/tokens/css";

// Tailwind v3 preset — maps token names to the CSS variables above
// tailwind.config.js
module.exports = {
  presets: [require("@lumen/tokens/tailwind-preset")]
};

// Typed JS/TS values, for use outside Tailwind/CSS (e.g. reading a duration
// in a JS animation, not just a class name)
import { spacing, radius, typography, motion, shadow } from "@lumen/tokens";
```

### Dark mode

Set `data-theme="dark"` on any ancestor element (typically `<html>` or your
app's root) to switch every color token to its dark-mode value — there is no
separate dark stylesheet to import. `@lumen/ui`'s `ThemeToggle` component
toggles this attribute; a consumer not using that component just needs to
set/remove it themselves (e.g. from a theme preference in local storage).

## Editing tokens

Edit the JSON files in `src/`, never `dist/` directly — `dist/` is
regenerated from source and any hand edit will be silently overwritten on
the next build.

| File | Covers |
|---|---|
| `src/primitives/color.json` | Raw color scale (Figma primitives) |
| `src/semantic/color.json` | Light/dark semantic mapping (background, text, border, brand, status, button, etc.) |
| `src/typography.json` | Type scale (font family + Display/Headline/Title/Label/Body/Overline/Caption/Code sizes) |
| `src/spacing.json` | Layout scale (Figma-sourced) + finer component `space` scale, both keyed by literal pixel value |
| `src/radius.json` | Corner radius scale |
| `src/shadow.json` | Component shadows (button, menu, toast) + `elevation.sm` — Figma-sourced; see "Shadow/elevation" below for what's still missing |
| `src/motion.json` | Duration, easing, opacity, and stagger tokens |
| `src/size.json` | Component-scale dimensions (header height, nav width, avatar/icon sizes, touch target) |
| `src/opacity.json` | Generic 12-step opacity primitive scale |
| `src/gradient.json` | Raw CSS `linear-gradient()` values (currently one: the upload-card header banner) |
| `src/divider.json` | Divider/separator styling |
| `src/breakpoint.json` | Responsive breakpoint thresholds, consumed by `typography.json`'s per-tier tablet/mobile overrides |
| `src/input.json` | Input-specific sizing/color tokens shared by several form components |
| `src/content-state.json` | `ContentState` composite's skeleton-bar geometry |
| `src/toast.json` | `Toast` composite's width/icon/close-button/progress-bar geometry |
| `src/icon-button.json` | `IconButton` primitive's sizing |

Then rebuild:

```bash
pnpm --filter @lumen/tokens build
```

## What's generated (and committed)

`dist/` is committed to this repo (not gitignored) so downstream apps can
consume it as a git/path dependency without running a build step first. It
is regenerated by CI on every change and should never be hand-edited —
`scripts/build.mjs` will overwrite it.

- `dist/css/variables.css` — CSS custom properties, `:root` (light) +
  `[data-theme="dark"]`
- `dist/tailwind-preset.cjs` — Tailwind v3 preset mapping token names to the
  CSS variables
- `dist/index.ts` — typed JS/TS exports of every token category listed
  above, for use outside Tailwind/CSS

## Shadow/elevation

Unlike an earlier version of this README claimed, Lumen does have real,
Figma-sourced shadow tokens (`src/shadow.json`, emitted as `--shadow-*` CSS
variables and the `shadow` export) — component-scoped shadows for `button`,
`menu`, and `toast`, plus one generic `elevation.sm` step. What's still
missing is a *complete* generic elevation scale (e.g. `elevation.md/lg/xl`)
beyond that single step — Figma hasn't published the rest of that scale yet.
See `docs/design-tokens.md` §6 for the full status and `docs/figma-sync.md`
for the sync record.

See `docs/figma-sync.md` at the repo root for which values are directly
sourced from Figma vs. engineering-extrapolated.
